# Состояния и правила внимания

[Назад в README](../../README.md)

Этот документ определяет состояния продукта, состояния UI и логику, которая решает, что показывать в первую очередь.

## Состояния проекта
### `Активный`
Проект можно двигать прямо сейчас.

Обязательные поля:
- название
- текущее следующее действие

Поведение UI:
- появляется в `Проекты > Активные`
- может появляться в `Сегодня`
- может быть завершён, отредактирован или заблокирован

### `Заблокирован`
Проект не может двигаться, пока не разрешится внешняя зависимость или не наступит будущая дата.

Обязательные поля:
- описание блокера
- ожидание
- дата возврата

Опциональные поля:
- действие фоллоуапа
- ожидаемый результат
- заметка о последнем отправленном сообщении

Поведение UI:
- покидает `Активные`
- появляется в `Проекты > Заблокированные`
- появляется в `Фоллоуапах`
- возвращается в поверхности внимания в выбранную дату

### `Завершён`
Проект завершён и больше не участвует в ежедневной зоне внимания.

Поведение UI:
- скрыт из операционных представлений по умолчанию
- виден в истории и в сводках еженедельного обзора

## Критические состояния внимания
### `Нет следующего действия`
Определение:
Существует активный проект без валидного следующего действия.

Почему это важно:
Обещание продукта нарушается, если у активного проекта нет следующего шага.

Отображение в UI:
- красный или высокоприоритетный предупреждающий бейдж
- выводится в `Сегодня`
- выводится в `Еженедельном обзоре`
- обычная карточка действия заменяется карточкой корректировки

Основное действие:
- `Определить следующее действие`

### `Просроченный фоллоуап`
Определение:
Заблокированный проект достиг или превысил дату возврата без разрешения ситуации.

Почему это важно:
Это основной механизм против забывания.

Отображение в UI:
- секция с наивысшим приоритетом в `Сегодня`
- верхняя группа в `Фоллоуапах`
- более сильный бейдж и метка времени, например `просрочено на 2 дня`

Основное действие:
- `Отправить фоллоуап`

### `Вернулся сегодня`
Определение:
У заблокированного проекта дата возврата наступила сегодня.

Отображение в UI:
- появляется выше стандартных рекомендаций
- средне-высокий приоритет, ниже просроченных фоллоуапов
- ярлык: `Вернулся сегодня`

Основное действие:
- `Проверить статус`

### `Устаревший проект`
Определение:
В активном проекте не было значимой активности дольше заданного порога.

Рекомендуемый порог:
- 7 дней для MVP, позже можно сделать настраиваемым

Отображение в UI:
- предупреждающий бейдж
- выводится в `Сегодня`, только если нет слишком большого количества более срочных элементов
- всегда показывается в `Еженедельном обзоре`

Основное действие:
- `Обновить следующее действие`

### `Входящие ожидают`
Определение:
Есть неуточнённые элементы во входящих.

Отображение в UI:
- баннер низко-среднего приоритета в `Сегодня`
- сильный сигнал счётчика при низком визуальном шуме

Основное действие:
- `Уточнить входящие`

## Правила ранжирования внимания
Движок внимания должен сортировать показываемые элементы в таком порядке:

1. `Просроченный фоллоуап`
2. `Вернулся сегодня`
3. `Нет следующего действия`
4. `Устаревший проект`
5. `Рекомендуемые следующие действия`
6. `Входящие ожидают`

### Эвристики ранжирования
Внутри состояния ранжировать по:
- сначала самой старой просроченной дате
- если проект только что вернулся, сначала по самым недавно заблокированным
- сначала стратегическим или закреплённым проектам, если такая метаинформация появится позже
- сначала по самой долгой неактивности для устаревших проектов

## Состояния экрана «Сегодня»
### Нормальное состояние
- существует как минимум одно рекомендуемое действие
- секции упорядочены по срочности

### Пустое состояние
Определение:
- нет активных проектов
- нет заблокированных фоллоуапов с наступившим сроком
- входящие пусты

Направление микротекста:
- кратко поздравить
- предложить захват или создание проекта

Основное действие:
- `Создать первый проект`

### Состояние высокой нагрузки
Определение:
- одновременно существует много срочных элементов

Поведение UI:
- ограничивать количество видимых рекомендаций
- суммировать остальные через контрол `Показать все`
- не показывать больше 5 основных элементов без прокрутки

## Состояния входящих
### В очереди есть элементы
- показывать количество и прогресс прохождения очереди
- по возможности всегда заранее подгружать следующий элемент

### Пустые входящие
Направление микротекста:
- показывать спокойное состояние завершённости
- усиливать чувство завершённой привычки, а не вины за продуктивность

Основное действие:
- `Что-нибудь захватить`

### Невалидная отправка уточнения
Примеры:
- заблокированный элемент без даты возврата
- новый проект без первого следующего действия

Поведение UI:
- встроенная валидация рядом с отсутствующим полем
- при исправлении сохранять видимым исходное содержимое

## Состояния деталей проекта
### Здоровый активный проект
- следующее действие присутствует
- есть недавнее движение
- нет срочных предупреждений

### Нет следующего действия
- заменить обычную карточку следующего действия карточкой вмешательства
- оставить `Заблокировать проект` доступным как вторичный путь

### Заблокирован
- верхняя карточка становится `Ожидаем`
- показывать дату возврата и сводку по блокеру над журналом активности
- сделать `Вернуть в активные` и `Обновить фоллоуап` основными действиями

### Завершён
- по умолчанию заморозить редактирование
- разрешить переоткрытие при необходимости

## Состояния еженедельного обзора
### Обзор готов
- показывать сводку текущей недели и сгруппированные проекты

### Обзор просрочен
Определение:
- пользователь не открывал текущий обзор в пределах заданного недельного окна

Поведение UI:
- баннер в `Сегодня`
- более заметная точка входа в `Обзор`

### Нет движения на этой неделе
- подчёркивать застой на уровне проектов, а не ноль закрытых задач
- предлагать пользователю либо переопределить следующее действие, либо осознанно поставить проект на паузу

## Состояния загрузки и пустоты
### Загрузка
- использовать скелетоны в форме реальных карточек и секций
- никогда не использовать полноэкранные спиннеры на основных поверхностях, если это не абсолютно необходимо

### Пустые коллекции
- каждое пустое состояние должно объяснять, ничего не существует или сейчас просто ничто не требует внимания
- использовать спокойную копию и одно очевидное действие

## Правила уведомлений
- Отправлять уведомления только для действительно чувствительных ко времени состояний внимания
- Предпочитать пакетные напоминания шумному спаму по одному элементу
- Уведомления должны вести по глубокой ссылке прямо к нужному корректирующему действию

## Правила доступности и ясности
- цвет статуса должен сопровождаться иконкой и ярлыком
- важные ярлыки срочности должны читаться без необходимости просматривать всю карточку
- кнопки должны использовать глаголы, а не общие подписи вроде `Отправить`

## Значения по умолчанию для MVP
- порог устаревания: `7 дней`
- количество верхних рекомендаций в `Сегодня`: `от 3 до 5`
- для заблокированного проекта обязательна дата возврата: `да`
- для заблокированного проекта обязательно поле ожидания: `да`
- для активного проекта обязательно следующее действие: `да`
