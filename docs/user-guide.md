# FocusLoop — руководство пользователя

FocusLoop помогает вести проекты по циклу **Capture → Clarify → Do → Review** (в интерфейсе — на английском, как в методологии GTD).

**Что значит Capture:** это не «ловить» и не калькируемое «захват». По смыслу — **сбор во входящие**: вы **быстро выгружаете** мысль, письмо или задачу **в Inbox в сыром виде**, **без** решения «это проект или архив» и без выбора даты. Разбор — отдельный шаг (Clarify). Так разгружается голова и появляется единое место, куда всё попало.

Дальше вы **уточняете** записи (проект, действие, ожидание от других, справка или архив), **делаете** следующие шаги и раз в неделю **смотрите обзор** портфеля.

Интерфейс **FocusLoop Web App-4** подключён к **FastAPI-бэкенду** (данные в PostgreSQL). Ниже — экраны и сценарии.

---

**Демонстрация продукта:** пошаговый сценарий с фразами для Inbox и что говорить зрителю — в **[demo-walkthrough.md](./demo-walkthrough.md)**.

## Запуск для работы

### Через Docker (рекомендуется)

Из каталога `backend`:

```bash
docker compose up --build
```

- Веб-приложение: **http://localhost:5173**
- API: **http://localhost:8000** (в контейнере фронт проксирует `/api/v1` к бэкенду)

### Локально (разработка)

1. Поднять PostgreSQL и бэкенд по [backend/README.md](../backend/README.md).
2. В каталоге `FocusLoop Web App-4`: `npm i`, затем `npm run dev`, с переменной **`VITE_API_BASE_URL`** указывающей на ваш API (например `http://localhost:8000/api/v1`).

## Навигация (боковая панель)

| Раздел | Назначение |
|--------|------------|
| **Today** | Сводка: входящие, просроченные напоминания, проекты без следующего действия, «застой», рекомендованные действия |
| **Inbox** | Очередь сырых записей и пошаговое «уточнение» |
| **Projects** | Список проектов (активные / заблокированные / завершённые) |
| **Follow-ups** | Заблокированные проекты с датой возврата и напоминаниями |
| **Reference** | Справочник: люди, команды, сервисы, документы |
| **Review** | Недельный обзор и быстрое добавление следующего действия |

В шапке сайдбара доступны **поиск** (заглушка под будущий функционал) и **быстрый сбор во входящие** (кнопка **+** / переход в Inbox — тот же смысл, что *Quick capture* в методологии).

## Inbox — сбор во входящие и уточнение

**Сбор (capture):** внизу экрана поле *Quick capture* и плавающая кнопка **Add** — новая **сырая** строка попадает во входящие, без типа и без дедлайна.

**Обработка:** показывается одна необработанная запись за раз. Выберите, что с ней сделать:

1. **Create project** — новый проект (название, заметки, опционально первое действие).
2. **Add to existing project** — следующее действие у уже существующего активного проекта.
3. **Create blocked follow-up** — проект ждёт кого-то извне: кого ждёте, причина, **дата возврата**, опционально связанный проект и текст напоминания.
4. **Create reference** — сохранить как справку (тип: человек / команда / сервис / документ), с контактом и заметками при необходимости.
5. **Archive** — убрать из входящих без превращения в проект (для справки).

**Previous / Skip for now** — листать очередь без решения по текущей карточке.

Цель — довести Inbox до нуля: все элементы либо уточнены, либо архивированы.

---

## Today

Экран агрегирует то, что требует внимания **сегодня**:

- предупреждение о ненулевом Inbox;
- просроченные follow-up;
- срок «вернуться» сегодня;
- активные проекты без следующего действия;
- раскрываемый список «застойных» и блок **ready to work on** с подсказками что делать дальше.

Отсюда удобно переходить во входящие, к проектам или к разделу follow-up.

---

## Projects

Фильтры: **Active**, **Blocked**, **Done**. Поиск по названию (иконка лупы).

Карточка показывает статус, следующее действие (если есть), подсказки для заблокированных и просроченных, дату последней активности.

Нажатие на карточку открывает **детали проекта**.

---

## Страница проекта

- **Next action** — главное действие; можно отметить выполненным и задать следующее, или **Replace action**.
- **Blocked** — если проект в ожидании: причина, кого ждёте, дата возврата, подсказка действия. Доступны **Unblock**, **Send reminder**, **Reschedule**.
- Если проект активен, но действия нет — предупреждение и кнопка **Add action**.
- Свернутые блоки **References** и **Activity** — связанные справки и журнал событий (сырой payload активности может быть JSON).

Раздел **More** внизу — заглушки под редактирование / паузу / удаление (под будущую реализацию в API).

---

## Follow-ups

Список заблокированных проектов с напоминаниями, сгруппирован по **Overdue**, **Due today** и раскрываемому **Upcoming**.

Действия: отправить напоминание (переход в контекст проекта), перенести дату, открыть проект. Пустое состояние означает, что нет ожидающих блокировок.

---

## Reference

Фильтрация по типу, поиск по названию и описанию. **Add reference** открывает диалог создания.

Связанные проекты в карточке — когда бэкенд начнёт отдавать связи, блок раскроется; сейчас список может быть пустым.

---

## Weekly Review (Review)

Сводка недели: сколько проектов продвинулись, сколько в блокировке, сколько **need attention**.

Ниже — блоки: follow-up на этой неделе, всё ещё заблокированные, нет движения 7+ дней, нет следующего действия. Для проектов без действия есть **Quick add** и переход в карточку.

При нуле проблем показывается **Review complete** и кнопка возврата на **Today**.

## Перед продакшен-деплоем

### Фронтенд (Web App-4)

- Файл **`src/app/data/mockData.ts` удалён** — демо-данные в коде фронта не использовались и не должны попадать в сборку.
- Убедитесь, что **`VITE_API_BASE_URL`** указывает на ваш продакшен API (например `https://your-domain.com/api/v1`), а CORS на бэкенде разрешает origin вашего фронта.

### Бэкенд

- В `docker-compose` или переменных окружения для продакшена задайте **`SEED_ON_START=false`**, чтобы при старте **не** подмешивались демо-проекты и записи из `app/seed.py`.  
  Локально seed по-прежнему удобен: данные создаются **только если база пустая** (повторный старт без очистки БД seed пропускает).

- Переменные БД, секреты и `BACKEND_CORS_ORIGINS` настройте под окружение; не используйте пароли из примера compose в продакшене.

### Безопасность и пользователи

Текущий MVP опирается на **одного пользователя по умолчанию** (`DEFAULT_USER_EMAIL` / `DEFAULT_USER_NAME`). Перед публичным запуском спланируйте аутентификацию и многопользовательский режим, если они нужны.

## Краткий чеклист рабочего дня

1. Открыть **Today** — закрыть критичное и заглянуть во **Inbox**, если есть счётчик.
2. Обработать **Inbox** пакетом (хотя бы несколько карточек).
3. По **Follow-ups** и **Projects** закрыть или перенести просроченное.
4. Раз в неделю пройти **Review**.

Если нужна англоязычная версия этого документа или отдельный раздел для администраторов (backup БД, миграции, мониторинг), его можно добавить рядом в `docs/`.
