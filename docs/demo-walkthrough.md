# Пример разбора задач — сценарий для демонстрации FocusLoop

**Capture** в терминах GTD — это **сбор сырых записей во входящие**, а не дословный «захват» и не «поймать задачу». Ниже для краткости мы используем английский термин у поля *Quick capture* в интерфейсе и русское **«сбор во входящие»** там, где речь о смысле.

Ниже — **готовая история**, которую можно разыграть за 10–15 минут: сначала показать пустой или почти пустой Inbox, затем **набросать строки** (только сбор, без разбора) и пройти уточнение. Так зрителю видно цепочку **Capture → Clarify → Do**, а не абстрактные кнопки.

---

## Роль и контекст

**Вы:** менеджер продукта / руководитель небольшой команды.  
**Цель дня:** разобрать хаос из головы и почты в проекты, действия и ожидания от других.

Можно перед демо **включить seed** (`SEED_ON_START=true` на пустой БД) или начать с **чистой базы** — тогда Inbox пустой и эффект «с нуля» сильнее.

---

## Часть 1. Быстрый сбор во входящие (30 секунд)

Откройте **Inbox**. Скажите вслух и вбейте в поле *Quick capture* **по одной строке**, после каждой нажимайте **Add** (или Enter, если настроено):

1. `Перезвонить Вике по бюджету Q2`
2. `Напомнить дизайну про дедлайн макетов лендинга`
3. `AWS подняла счёт — разобраться с биллингом`
4. `Идея: опрос NPS после онбординга`
5. `Статья про GTD — почитать вечером`

**Что сказать зрителю:** «Сначала ничего не классифицирую — только снимаю трение с головы. Всё лежит во входящих.»

---

## Часть 2. Пошаговое уточнение (ядро демо)

Обрабатывайте карточки **сверху вниз**. Для каждой кратко проговорите мысль и нажмите нужный вариант.

### 1) «Перезвонить Вике по бюджету Q2»

- **Смысл:** это конкретное действие, скорее всего уже есть или будет отдельный проект про бюджет.
- **Вариант A (проще для демо):** **Add to existing project** → выбрать любой активный проект (или создать проект из следующей карточки и вернуться).
- **Вариант B:** **Create project** «Бюджет Q2» → первое действие «Позвонить Вике по своду цифр».

**Реплика:** «Это не справка и не архив — это следующий шаг по теме бюджета.»

### 2) «Напомнить дизайну про дедлайн макетов лендинга»

- **Смысл:** действие по существующему направлению (лендинг).
- **Действие:** **Add to existing project** → проект вроде «Лендинг продукта» → next action: `Написать в #design: дедлайн макетов — [срок]`.

**Реплика:** «Входящее превращается в одну строку следующего действия на доске проекта.»

### 3) «AWS подняла счёт — разобраться с биллингом»

- **Смысл:** это скорее новая тема с несколькими шагами.
- **Действие:** **Create project**  
  - Title: `Биллинг AWS`  
  - Notes: `Неожиданный рост счёта, проверить счета и сервисы`  
  - First action (опционально): `Скачать детализацию за последний месяц в консоли AWS`

**Реплика:** «Когда тема не укладывается в одну фразу — завожу проект и первое физическое действие.»

### 4) «Идея: опрос NPS после онбординга»

- **Смысл:** идея на будущее, сейчас не делать.
- **Действие:** **Create project** с минимальным следующим шагом **или** **Archive**, если в демо показываете «не за всё нужен проект сразу».  
  - Разумный компромисс для демо: **Create project** `NPS после онбординга`, первое действие `Сформулировать гипотезу и критерий успеха (30 мин)`.

**Реплика:** «Идея без следующего шага снова станет фоновым шумом — я обязую себя первым маленьким шагом.»

### 5) «Статья про GTD — почитать вечером»

- **Смысл:** не проект работы, не ждём никого — можно убрать из активного внимания.
- **Действие:** **Archive**.

**Реплика:** «Входящие — не склад всего подряд. Если это справочно — в архив; если станет проектом — снова **соберу** это во входящие новой строкой, когда будет актуально.»

## Часть 3. Что показать после Inbox (2–3 минуты)

После разбора откройте по порядку:

| Экран | Что сказать |
|--------|-------------|
| **Today** | «Сводка подтягивает непрочитанное во входящих, просрочки, проекты без действия — всё в одном месте на старт дня.» |
| **Projects** | «Фильтр Active / Blocked / Done — вижу портфель. Новый проект про AWS и NPS уже здесь.» |
| Открыть **проект AWS** | «Следующее действие на виду; выполнил — отмечаю и задаю новое.» |
| **Follow-ups** | «Если бы я добавил ожидание от человека с датой — карточка попала бы сюда и в Today при просрочке.» *(при желании добавьте одну карточку blocked follow-up перед демо)* |
| **Reference** | «Люди и команды можно вести отдельно от проектов, чтобы не плодить дубли в заметках.» |
| **Review** | «Раз в неделю — что застыло, что без следующего шага: не даём списку загнить.» |

---

## Опционально: одна карточка «ожидание от других»

Чтобы **Follow-ups** и блок на **Today** были не пустыми:

1. В **Inbox** добавьте: `Ждём юридический отзыв по договору партнёрки`.
2. **Create blocked follow-up:**  
   - Related: проект «Партнёрский договор» (создайте при необходимости быстрым проектом из другой строки).  
   - Waiting on: `Юридический отдел`  
   - Reason: `Проверка отзыва`  
   - Return date: **вчера** или **сегодня** (чтобы в списке было наглядно).

Тогда в демо есть история: «Вот проект в ожидании; просрочка подсвечивается, можно перенести дату или пнуть процесс.»

---

## Как «лучше» показывать зрителю (короткие советы)

1. **Одна мысль — одна фраза во входящих** — так проще жать Clarify без простыней текста.  
2. **Всегда проговаривайте вслух:** «Это действие / проект / ожидание / не сейчас».  
3. **Не исправляйте ошибки за кадром** — если промахнулись с типом, покажите, как это потом чинится в **Project** (замена действия, разблокировка).  
4. **Закончите на позитиве:** Inbox пустой или почти пустой, в **Today** понятные следующие шаги.
