# Task Template

[Назад в README](../../README.md)

## Зачем
Этот шаблон нужен, чтобы задачи были понятными до начала разработки.

Если задача не может быть заполнена по этому шаблону, скорее всего она еще слишком сырая.

## Шаблон

### 1. Короткое название
Одной фразой, без воды.

Пример:
- `Добавить block project endpoint`
- `Показать stale projects на Today`

### 2. Контекст
Что это за часть продукта и зачем мы туда идем?

Пример:
`На экране Today нужно показывать stale projects, чтобы пользователь видел проекты без движения и не забывал про них.`

### 3. Что нужно сделать
Конкретный ожидаемый результат.

Формат:
- добавить ...
- изменить ...
- показать ...
- запретить ...

### 4. Что НЕ нужно делать
Очень важный раздел для студенческой команды.

Нужно явно написать, что вне scope.

Пример:
- не делать красивую сортировку;
- не трогать mobile;
- не менять API кроме одного endpoint;
- не делать рефакторинг соседних модулей.

### 5. Где это живет
Список предполагаемых файлов, модулей или слоев.

Пример:
- `backend/modules/attention`
- `GET /today`
- `web/app/today`

Если точное место неизвестно, пишем хотя бы уровень:
- `backend`
- `web`
- `mobile`

### 6. Ожидаемое поведение после изменения
Что должен увидеть пользователь или система после выполнения задачи?

Пример:
`Если у active проекта не было активности 7 дней, он появляется в секции stale projects на Today.`

### 7. Критерии приемки
Проверяемые пункты.

Формат:
- [ ] ...
- [ ] ...
- [ ] ...

Пример:
- [ ] stale project попадает в `Today`
- [ ] секция не показывает done projects
- [ ] не ломается existing today response

### 8. Как проверить
Минимальный сценарий проверки.

Пример:
1. Создать active project.
2. Выставить `last_activity_at` старше 7 дней.
3. Открыть `GET /today`.
4. Убедиться, что проект появился в stale section.

### 9. Риски / вопросы
Что может быть непонятно или опасно?

Пример:
- непонятно, считать ли blocked project stale;
- непонятно, где лучше вычислять это состояние.

## Короткая версия шаблона
Если задача совсем небольшая, достаточно такого мини-формата:

```text
Название:

Что сделать:

Что не делать:

Где менять:

Критерии приемки:

Как проверить:
```

## Обязательное правило
Разработчик не должен начинать задачу, если:

- не понимает цель;
- не понимает scope;
- не понимает критерии приемки.
