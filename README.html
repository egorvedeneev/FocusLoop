FocusLoop MVP

Персональная productivity-система для перегруженных knowledge workers. Это не обычный task manager, а workflow-продукт, построенный вокруг цикла capture -> clarify -> do -> review.

Project-first Always next action Blocked is not lost Review over backlog Веб + будущий mobile

Цель продукта

  • Фиксировать входящие обязательства и идеи.
  • Разбирать их в проекты, следующие шаги, follow-up'ы и справочные сущности.
  • Держать каждый активный проект в движении за счет ясного next action.
  • Не терять заблокированную работу и возвращать ее по дате.
  • Смотреть на прогресс в недельном обзоре на уровне проектов.

UX-правила
  • Не показывать плоский список задач как главный рабочий экран.
  • Всегда объяснять, почему элемент требует внимания сейчас.
  • Явно различать active и blocked проекты.
  • Показывать на главном экране только несколько рекомендуемых действий.

Основные пользовательские сценарии

Today

Понять, что требует внимания прямо сейчас, и выбрать из короткого списка.

Inbox Clarify

Превратить сырое входящее в проект, следующий шаг, follow-up или reference.

Project Work

Сделать текущий next action главным элементом экрана и упростить его обновление.

Blocked Follow-Up

Безопасно поставить проект на ожидание, сохранить блокер и вернуть позже.

Weekly Review

Увидеть движение, блокировки, застой и проекты без следующего шага.

Attention model

Состояния

  • Overdue follow-up
  • Returned today
  • No next action
  • Stale project
  • Recommended next actions
  • Inbox waiting

Приоритет

  1. Overdue follow-up
  2. Returned today
  3. No next action
  4. Stale project
  5. Recommended next actions
  6. Inbox waiting

Ключевые правила

  • Каждый active project обязан иметь текущий next action.
  • Blocked project обязан иметь валидный follow-up.
  • Today вычисляется из attention states.
  • Weekly review смотрит на проекты, а не на список задач.

Сущность Назначение
Project Главная единица работы.
ProjectAction Конкретное действие внутри проекта, включая next action.
InboxItem Сырое входящее, которое еще не разобрано.
FollowUp Запись о блокировке и механизме возврата проекта.
ReferenceEntity Люди, команды, сервисы и другие справочные сущности.
ActivityEvent История изменений для таймлайнов, summary и review.

REST API contract

Базовый префикс: /api/v1

Ключевые endpoints

  • POST /projects
  • GET /projects?status=active
  • GET /projects/{project_id}
  • POST /projects/{project_id}/next-action
  • POST /project-actions/{action_id}/complete
  • POST /inbox-items/{id}/clarify
  • POST /projects/{project_id}/block
  • POST /projects/{project_id}/unblock
  • GET /today
  • GET /reviews/weekly

Правила API

  • Отдавать готовые payloads для Today и Weekly review.
  • Держать единый формат ошибок.
  • Проверять доменные ограничения на backend, а не только в UI.

Пример ошибки

{
  "error": {
    "code": "PROJECT_REQUIRES_NEXT_ACTION",
    "message": "Active project must have a current next action",
    "details": {}
  }
}
